Choose a rating between 400 and 2800, and Snail Chess plays like a Lichess player at that level,
including how long it thinks and when it resigns. Disable human play to use it as a fast search
engine at full strength.

Human moves are generated by [Ganglia](https://github.com/CodeAdopter/Snail-Ganglia), a neural
network trained on Lichess games. The network is included with the engine, so no additional
downloads are needed.

## Why

Snail Chess started as a project to build a fast chess engine in my own programming language,
[Snail](https://github.com/CodeAdopter/Snail). That part went well: version 1.19 plays at about
3280 Elo, searches 20 million positions per second and has a binary size of just 95 KB.

Then I played against it at my own level, and it was no fun. A strong engine with reduced
strength does not play like a weaker human: it plays ten excellent moves and then blunders a
piece.

Version 2.0 takes a different approach. A neural network trained on real Lichess games predicts
which move a player of the selected rating would make, based on the position and the remaining
clock time. The original search engine is still there and runs at full strength when human play
is disabled.

## What you get

- **Any rating from 400 to 2800**, on the Lichess scale.
- **Human moves.** On unseen blitz games, the network's top prediction matches the move actually
  played about 56% of the time.
- **Human timing.** Think times are based on how long people take, with faster decisions as the
  clock runs low. It can also premove, particularly for recaptures and in time trouble. Premoves
  are played immediately and use no clock time.
- **Human resignations.** It resigns when a player of that rating would. This can be disabled.
- **Full strength when you want it.** Disable human play to use the engine's normal search.

The network was trained on bullet, blitz, rapid and classical games.

## Use it

1. Download the latest build from the
   [releases page](https://github.com/CodeAdopter/Snail-Chess/releases), for Windows or Linux.
   Human play requires version 2.0 or later.
2. Add Snail Chess to any UCI-compatible chess GUI.
   [Snail Chess GUI](https://github.com/CodeAdopter/Snail-Chess-Gui) configures it automatically,
   and it works with other UCI GUIs too.
3. Enable `UCI_LimitStrength` and set `UCI_Elo` to the rating you want to play against. These are
   standard UCI options, so some GUIs show them through their own strength settings.

For the most realistic play, use a timed game. Clock time affects move selection: a player with
ten seconds remaining may choose differently from one with ten minutes. Without clock information,
the engine assumes a 10-minute game with plenty of time remaining.

## UCI guide

Snail Chess supports the standard UCI protocol and can be used with any compatible GUI or script.
Human play adds two pieces of information to each response: the predicted think time, and whether
the engine has resigned. Programs that ignore this information still receive a legal `bestmove`.

In the examples below, lines beginning with `>` are commands sent to the engine. All other lines
are engine responses.

### 1. Enable human play

```
> uci
  id name Snail Chess 2.0
  option name UCI_LimitStrength type check default false
  option name UCI_Elo type spin default 1500 min 400 max 2800
  ...
  uciok
> setoption name UCI_LimitStrength value true
> setoption name UCI_Elo value 1500
> isready
  readyok
```

`UCI_Elo` uses Lichess ratings for the current time control. For example, 1500 represents a
1500-rated blitz player in blitz games and a 1500-rated rapid player in rapid games.

You can also specify the opponent with the standard `UCI_Opponent` option, which accepts a title,
rating, player type (`human` or `computer`) and name:
`setoption name UCI_Opponent value none 1700 human Anna`. If omitted, the engine assumes the
opponent has the same rating.

### 2. Start each game with `ucinewgame`

The engine tracks clock information throughout each game. `ucinewgame` resets this tracking for a
new game.

### 3. Request a move with the move history and both clocks

```
> ucinewgame
> position startpos moves e2e4 e7e5 g1f3 b8c6 f1c4
> go wtime 293000 btime 296000 winc 0 binc 0
  info depth 1 seldepth 1 score cp -12 wdl 464 37 499 nodes 1 time 55 pv h7h6
  info string human move h7h6 prob 0.240 think 6.97 expected 0.483 resign 0.0008 check 1.00 penalty 1.3 kept 5 of 5
  bestmove h7h6
```

- **Provide the full move history, not just the current position.** Use
  `position startpos moves ...`, or `position fen ... moves ...` for a game that starts from a
  set-up position. The network uses the previous eight positions and repetition information.
- **Provide accurate clock times and increments** with `wtime`, `btime`, `winc` and `binc` from
  the start of the game. The engine uses them to determine the time control, how much time
  pressure it is under, and how long the opponent spent on their previous move. Time controls
  follow Lichess classifications, using the initial time plus 40 increments: under 3 minutes is
  bullet, under 8 blitz, under 25 rapid, and 25 or more classical.
- **Without clock information**, such as with `go movetime`, `go depth` or `go nodes`, the engine
  assumes a 10-minute game with a full clock. With `go infinite`, it reports its selected move but
  waits for `stop` before sending `bestmove`.

Up to a rating of about 2500, a response takes under 100 ms. At the highest ratings it takes up to
about 500 ms, because the engine runs a deeper search to check candidate moves.

| Field | Meaning |
|---|---|
| `bestmove` | Selected move. Repeated requests may produce different moves. |
| `score cp`, `wdl` | Expected outcome for a player of the selected rating, as win, draw and loss probabilities per 1,000 games and a centipawn-equivalent score. This is not a search evaluation. |
| `prob` | Probability that a player of the selected rating chooses this move, from 0 to 1. |
| `think` | Predicted think time in seconds. |
| `expected` | Expected score, from 0 (loss) to 1 (win). |
| `resign` | Probability of resignation on this move. |
| `check ...` | Search verification details: how strictly candidate moves were checked, and how many remained eligible for selection. |
| `premove` | Ends the line when the selected move is a premove. |

### 4. Apply the predicted think time

The engine returns its move immediately. The GUI should play it `think` seconds after the
opponent's move and deduct that time from the engine's clock. The predicted think time is capped
at one-eighth of the remaining clock time.

When the line ends with `premove`, `think` is 0. Play the move immediately without deducting clock
time, as Lichess does for a premove:

```
> position startpos moves e2e4 d7d5 e4d5
> go wtime 298000 btime 299000 winc 0 binc 0
  info depth 1 seldepth 1 score cp -13 wdl 464 35 501 nodes 1 time 47 pv d8d5
  info string human move d8d5 prob 0.822 think 0.00 expected 0.481 resign 0.0015 check 1.00 penalty 1.3 kept 5 of 5 premove
  bestmove d8d5
```

GUIs and match runners that cannot manage think times can delegate the delay to the engine. When
`Human Timing` is enabled, the engine waits for the predicted think time before sending
`bestmove`.

### 5. Handle resignations

When the engine resigns, it sends a separate line before `bestmove`:

```
> position startpos moves e2e4 e7e5 g1f3 d8h4 f3h4
> go wtime 297000 btime 295000 winc 0 binc 0
  info depth 1 seldepth 1 score cp -292 wdl 141 31 828 nodes 1 time 51 pv f8c5
  info string human move f8c5 prob 0.150 think 2.09 expected 0.157 resign 0.2203 check 1.00 penalty 1.3 kept 6 of 6
  info string human resign
  bestmove f8c5
```

- When `info string human resign` is received, end the game as a loss by resignation without
  playing `bestmove`.
- The engine still sends `bestmove` to remain UCI-compatible. GUIs that do not support the
  resignation line can ignore it, and the game continues.
- In this example, a 1500-rated Black player has lost the queen without compensation, resulting in
  a 22% resignation probability (`resign 0.2203`). Repeated requests may result in the player
  continuing instead. In an equal position, the resignation probability is about 0.1% per move.
- Disable `Human Resign` to prevent resignations.
- Match runners that adjudicate games by score can enable `Human Resign Score`. Resignations are
  then also reported as `score cp -30000`.

### Basic integration loop

```
when it is the engine's turn:
    send   position startpos moves <every move so far>
    send   go wtime <ms> btime <ms> winc <ms> binc <ms>
    read lines until "bestmove <move>":
        info string human move ... think <seconds> ...    keep <seconds>; "premove" may end the line
        info string human resign                          the engine resigns
    if it resigned:   the engine loses by resignation
    if premove:       play <move> now, and leave the engine's clock as it was
    otherwise:        play <move> <seconds> after the opponent moved,
                      and deduct <seconds> from the engine's clock
```

### Full-strength mode

With `UCI_LimitStrength` disabled, which is the default, Snail Chess is a conventional search
engine. It searches within the limits given to `go`, reports `info depth ... score cp ... pv ...`
lines with search evaluations, and sends `bestmove` with a `ponder` move. `Threads` sets the
number of search threads. `MultiPV` is not supported: the engine reports a single line.

## Options

| Option | Type | Default | Description |
|---|---|---|---|
| `UCI_LimitStrength` | check | false | Enables human-like play at the rating set by `UCI_Elo`. |
| `UCI_Elo` | spin, 400 to 2800 | 1500 | Target Lichess rating. |
| `UCI_Opponent` | string | | Opponent details in standard UCI form, such as `none 1700 human Anna`. The rating is used to adjust expected outcomes. |
| `Human Resign` | check | true | Enables human-like resignations. |
| `Human Timing` | check | false | Delays `bestmove` by the predicted think time, for GUIs that cannot apply it themselves. |
| `Human Pace` | spin, 25 to 400 | 100 | Adjusts think time as a percentage of the predicted duration. |
| `Human Premove` | check | true | Enables human-like premoves. |
| `Human Temperature` | spin, 0 to 300 | 100 | Controls move selection randomness. At 100, moves follow the learned probabilities; at 0, the most likely move is always selected. |
| `Human Resign Score` | check | false | Also reports resignations as `score cp -30000`, for match runners. |
| `Human Net` | string | `<embedded>` | Loads a custom Ganglia network (`.gnet`). Set to `<none>` to use rating-limited search without a human network. |
| `Human Time Net` | string | `<none>` | Loads a custom Ganglia think-time network (`.tnet`). |
| `Style` | combo: Balanced, Aggressive, Passive | Balanced | Adjusts playing style. Aggressive prefers checks and moves toward the enemy king and avoids equal trades; Passive does the opposite. |
| `Threads` | spin, 1 to 256 | 1 | Number of search threads used in full-strength mode. |

Additional options are available for testing and tuning:

- `Human Check`, `Human Check Nodes`, `Human Check Penalty`, `Human Check Temperature`,
  `Human Penalty Centi`, `Human Tail`, `Human Net Elo`, `Human Check Moves` and `Human Blunder`
  override the rating-specific parameters that control playing strength. They are intended for
  testing and tuning the rating calibration. Leave them at their defaults to play at the
  calibrated strength for `UCI_Elo`.
- `MasterBook`, `GambitBook`, `PassiveBook`, `NeutralBook` and `MemoryFile` configure opening
  books and game memory used by the search engine. Snail Chess GUI configures these automatically.

## Build it

Building from source requires the [Snail compiler](https://github.com/CodeAdopter/Snail). The
network is included in the source at `src/v3-small-9x192.gnet` and embedded during compilation.

```
snailc build -c release
```
